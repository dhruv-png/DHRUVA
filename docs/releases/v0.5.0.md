## Summary

S04 made events durable. This release makes them arrive — and makes a backtest
receive them the same way production does.

The outbox now has a relay, a transport, a dead-letter queue an operator can act
on, a consumer idempotency ledger, and a job runtime. Beside the live transport
sits a replay adapter reading the same persisted rows, and **both pass one
unchanged conformance suite**. That suite is the release's most load-bearing
artefact: ADR-067 says live delivery and replay are peers, and fourteen shared
assertions are what make that claim testable rather than aspirational.

## What shipped

- **The event envelope and its codecs** (ADR-061). Canonical JSON, exact domain
  representations, float refused at any depth, and a type with no codec refused
  rather than `str()`-ed.
- **`EventPublisher` and `EventStream` ports** (ADR-067), with three
  implementations: Redis Streams, an in-memory loopback, and replay.
- **The outbox relay** (ADR-062, ADR-063) — `SKIP LOCKED` claims, leases rather
  than held locks, publish-then-mark, and eighteen failure-injection tests.
- **Dead-letter inspection and explicit re-queue** (ADR-064) via `dhruva-dlq`.
- **The consumer idempotency ledger** (ADR-065) and migration `0006`.
- **Calendar-aware scheduling** (ADR-066) and its Celery beat adapter.
- **The Celery job runtime** — application, worker entrypoint, task registration
  and job registry, all built from settings rather than imported as globals.
- **Replay as an `EventStream`** (ADR-069), with `as_of` enforced in the query.

## Defects found and fixed

Each was found by a test, and each had been green until the test that caught it
existed.

- **The outbox wrote payloads with a different encoder than the relay reads them
  with.** A `Decimal` committed by a producer arrived at a consumer as a string —
  same characters, different type, no error anywhere. Both sides were internally
  consistent, so every isolated test passed; the first end-to-end test found it.
- **`Celery.task()` leaks a job into every application built afterwards.** Its
  `shared=True` default appends a finalizer to a module-level list.
- **The retry policy raised `OverflowError` at 1024 attempts**, reachable from a
  re-queued dead letter. Found by a property test.
- **The relay reclaimed dead-lettered rows forever.** The partial index carried
  `dead_lettered_at IS NULL`; the claim query did not.
- **`__version__` was a release behind**, so a deployed S04 build reported
  `0.3.0`. Now compared against the changelog by a test.
- **The deployment lockfiles had drifted from `pyproject.toml`.** `uv add`
  maintains `uv.lock` only. Now compared by a test.
- **`mypy --strict` had 22 errors** in the relay's integration tests, red since
  that file landed.
- **The ADR corpus test asserted a frozen range**, red since ADR-060.

## Architectural decisions recorded

ADR-061 through ADR-069 were accepted before implementation. Two corrections
were recorded during it, neither requiring an ADR change:

- **Explicit Redis stream ids were withdrawn** (design §7 erratum). Redis
  requires an explicit entry id to exceed the stream top, and retry is per
  message while a stream is per aggregate type — so a retried sequence arrives
  behind later ones and is refused.
- **Trace context is transport metadata, not domain state** (design §16b).
  Putting a `traceparent` on the envelope would make tracing part of what
  `canonical_json` hashes, so two runs of the same replay traced differently
  would serialise differently and ADR-069's determinism would be gone.

The conformance suite was also **scoped** rather than weakened: redelivery is
what ADR-062 promises of a live transport, not a property of `EventStream`, and
the assertion moved to the Redis tests when replay revealed the distinction.

## Dependency changes

`redis==6.4.0` and `celery==5.5.3` added as runtime dependencies;
`testcontainers[postgres,redis]==4.9.1` for development. Each carries a
provenance entry that `test_toolchain_config.py` enforces, and all three
lockfiles are regenerated: `uv.lock` by uv's own resolver, and
`requirements.lock` and `requirements-dev.lock` by the canonical
`uv pip compile` commands recorded in their own headers.

## Migration notes

`0003`–`0006` extend the outbox and add the idempotency ledger. All four are
additive and reversible; the full chain runs up → down → up with an empty
autogenerate diff.

## Rollback procedure

`alembic downgrade 0002_example_tick` reverses everything S05 added. Do it with
consumers stopped: dropping `processed_event` discards every consumer's record
of what it has processed, so the first delivery afterwards is treated as new.

## Known limitations

- **Trace context is not propagated across the bus** (TD-S05-16). The decision
  is made; the consumer half has nowhere to attach an extracted context, because
  `EventStream.read` returns a batch and the port exposes no per-delivery scope.
  Completing it needs a port addition — an ADR-level change — or the consumer
  runtime that would own the scope.
- **No `TradingCalendar` implementation exists**, so no beat entries are
  registered. The scheduling policy and beat adapter are complete and tested;
  they wait on a calendar adapter.
- **The job registry is empty.** S05 builds the runtime; the first job belongs
  to the subsystem that needs one.
- **No benchmark covers the S05 paths** (TD-S05-11), and **ADR-060 A1's Linux CI
  benchmark job remains the stop-the-line item before S06**.
- **Mutation testing not run** (TD-12).
- **A replay *engine* driving a strategy is not built** — the adapter is. The
  engine belongs to the subsystem that has a strategy.
