## Summary

The platform's four cross-cutting capabilities, plus its first runtime component.

Configuration is now typed, validated once at a composition root, and injected —
no module anywhere reads the environment, enforced by boundary rule **R5**.
Logging is structured with a redaction control that is *tested*, not asserted.
Errors are a closed taxonomy with stable codes. Correlation propagates
automatically. And `dhruva-api` serves `/health`, `/ready` and `/metrics` —
observability arriving with the component rather than being retrofitted at S41.

## Dependency changes

Seven runtime dependencies added, each pinned exactly and justified in the design
document: `pydantic`, `pydantic-settings`, `structlog`, `fastapi`, `uvicorn`,
`prometheus-client`, `opentelemetry-api`.

One optional extra: `tracing` (`opentelemetry-sdk`, OTLP HTTP exporter). A test
asserts the SDK is **not** a runtime dependency (ADR-040).

Both hash-pinned lockfiles regenerated: `requirements.lock`, `requirements-dev.lock`.

## Migration notes

**No migration required.**

Verified explicitly rather than assumed:

- **No database schema.** S02 opens no connection and creates no table. The
  `DatabaseSettings` and `RedisSettings` schemas are defined but unused.
- **No configuration is mandatory.** Every setting has a safe default, and a
  developer with an empty environment gets a working local process. Existing
  `.env` files remain valid.
- **No breaking API change.** S01 exposed no runtime API.
- **New optional variables**, all documented in `infra/.env.example`:
  `DHRUVA_APP__*`, `DHRUVA_LOG__*`, `DHRUVA_DB__*`, `DHRUVA_REDIS__*`,
  `DHRUVA_OTEL__*`.

**One behavioural change worth knowing.** Deployed environments (`staging`,
`production`) now **refuse to start** if debug is enabled, a credential is still a
development placeholder, or the log format is forced to `console`. This is
intended (FR-04) and will surface as a startup failure naming the field.

## Rollback procedure

```bash
# 1. Return to the previous release.
git checkout v0.1.0

# 2. Reinstall the dependency set for that tag.
#    v0.1.0 had no runtime dependencies; this removes the seven added here.
cd backend && uv pip install --require-hashes -r requirements-dev.lock

# 3. Verify.
cd .. && make check
```

**What rollback does not undo — read before relying on it:**

| Item | Reversible? | Notes |
|---|---|---|
| Source and tests | **Yes** | Fully. `v0.1.0` is a green tag. |
| Dependency set | **Yes** | v0.1.0 had none; reinstalling from its lockfile is clean. |
| Configuration variables | **Yes** | All optional; unset them or leave them. |
| Database state | **N/A** | S02 touches no database. |
| **ADR corpus** | **No** | ADR-031 … ADR-041 are accepted and immutable (ADR-027). Rolling back code does not un-decide them. Superseding is the only sanctioned reversal. |
| **Emitted log records** | **No** | Records already written keep the v0.2.0 schema. |
| **Published metrics series** | **No** | A Prometheus instance that scraped this build retains the series. No instance exists yet. |

There is no in-flight state, no queue, and no external side effect. Rollback is
genuinely a `git checkout` — which will not be true from S04 onward, and that is
precisely why this section exists now.

## Known limitations

Full register in `docs/subsystems/S02-core-runtime.md` §13. Highest priority:

- **TD-01 / TD-02 (HIGH)** — canonical `uv.lock` and validation on Python 3.12,
  both blocked on access to a 3.12 host.
- **TD-06 (ACCEPTED)** — value-based redaction cannot see a transformed secret.
- **TD-07 (ACCEPTED)** — `contextvars` do not reach threads without the wrapper.

## Verification environment

Validated on Python 3.10 with mypy targeting 3.12, because the 3.12 build
artefact is unreachable from the build sandbox. A compatibility shim bridges
`StrEnum`, `Self`, `datetime.UTC` and `logging.getLevelNamesMapping`; it lives
outside the repository and never ships. See `docs/BUILD.md`.
